# Interview Overview｜访谈概览

## 1. Interview Purpose｜访谈目的

1. Validate whether the patterns identified from the initial corpus also appear in real users.
    验证前期语料研究中发现的问题是否真实存在于用户的实际经历中。
2. Understand users’ concrete communication situations, emotions, behaviors, and existing workarounds.
    了解用户真实的沟通情境、情绪、行为以及目前的解决方式。
3. Translate user evidence into product decisions and identify which hypotheses need further validation.
    将用户证据转化为产品决策，并判断哪些假设需要继续验证。


## 2. Participant Selection｜访谈对象选择

访谈对象有意覆盖不同沟通场景和不同类型的沟通困难。

## 3. Interview Question Design｜访谈问题设计

The interviews followed a hypothesis-driven structure rather than a fixed questionnaire.
访谈不是固定问卷，而是围绕已有假设，根据用户回答动态追问。

Stage 阶段	Focus 重点
1. Concrete Event / 具体事件	Ask about a recent real communication situation / 追问最近发生的真实事件
2. Emotion & Behavior / 情绪与行为	Explore what the user felt and did / 了解用户当时的情绪和行为
3. Current Workaround / 当前解决方式	Understand how the user currently handles the problem / 了解用户现在如何解决
4. Existing Tools / 现有工具	Compare friends, AI, search, notes, etc. / 了解用户使用朋友、AI、搜索、备忘录等方式的情况
5. Product Concept / 产品概念	Test reactions to Murmur’s core concept / 验证用户对 Murmur 核心概念的反应
6. Usage Conditions / 使用条件	Explore when and why users would choose Murmur / 了解用户什么时候会选择使用
7. Input & WTP / 输入与付费	Test input burden and early willingness-to-pay signals / 验证输入成本和初步付费意愿


## 4. Use of Interview Materials｜访谈材料如何使用

1. Preserve user statements and concrete events as evidence.
    保留用户原话和具体事件作为证据。
2. Structure each interview into hypotheses, evidence, findings, and product implications.
    将每次访谈整理为假设、证据、发现和产品影响。
3. Compare findings across interviews to identify repeated patterns and contradictions.
    横向比较不同访谈，识别重复出现的模式和相互矛盾的证据。
4. Use the findings to update product priorities and the next round of interview questions.
    根据发现调整产品优先级，并修改下一轮访谈问题。


## 5. Interview Quality Evaluation｜访谈质量评估

每次访谈使用三个指标进行评估，每项 1–5 分。

## 6. Hypothesis Development & Validation｜假设提出与验证

1. Initial hypotheses were derived from the 108-sample corpus.
    初始假设来自前期 108 条语料的分析。
2. Each interview tested existing hypotheses while allowing new findings to emerge.
    每次访谈既验证已有假设，也允许新的发现出现。
3. Hypotheses were updated according to the evidence rather than treated as fixed conclusions.
    根据实际证据调整假设，而不是把初始假设当成固定结论。
4. Repeated findings across interviews were treated as stronger signals, while single-user findings remained hypotheses for further validation.
    多次访谈重复出现的发现作为更强的信号，单个用户的新发现则保留为待验证假设。

## 7. Core Findings｜核心结论

1. “帮我看”是独立需求。
    Users may already know what they want to say, but still need help checking whether it is appropriate.
2. 输入成本本身会影响使用。
    Re-explaining a difficult situation can increase the user’s emotional and cognitive burden.
3. 通用 AI 已经是重要替代方案。
    Murmur cannot differentiate through message generation alone; context understanding and communication-specific support are important.
4. 个性化沟通档案值得继续验证。
    Users showed interest in having the AI remember communication styles, relationship context, and past patterns.
5. “写 → 看 → 反思”是一个待验证的长期方向。
    Some users expressed interest in using AI not only to solve individual messages, but also to learn from their communication patterns over time.
